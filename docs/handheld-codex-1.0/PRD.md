# 掌上助手 1.0 产品需求

日期：2026-10-04。状态：实施依据。已安装 0.5.1 受限预览，完整 1.0 尚未通过验收。

本方案把掌上助手定义为随身使用的 Codex 工作终端。用户拿起掌机，应能了解电脑上的已有任务、处理需要自己的决定、继续安排工作，并检查成果。是否达到这个使用体验，是 1.0 的交付标准。

本文件是接下来 Codex 掌机主线的依据。原有多来源仪表盘方案及 R05 交接作为历史资料保留；DeepSeek、MiMo、天气和通用电脑监控暂不进入本版交付范围。

## 用户目标与使用边界

用户提出五项要求：漂亮的 AI 产品界面；保留 Codex Desktop 的关键要素；好的实体按键交互；离开电脑也能控制原有 Codex 工作；随时知道 Codex 运行得怎样。

主要设备为当前 TRIMUI Smart Pro，原生应用，1280×720 横屏。保留中文名称“掌上助手”和已经验证的按住 Y 说话操作。

“没有电脑”暂按电脑不在身边理解：远端电脑和 Codex 仍需要开机、联网。电脑关机时应显示离线及最后更新时间；不能宣称任务仍在执行。云执行环境不属于当前实现。

本版覆盖两个场景：

1. 家中离开书桌，在掌机查看和继续工作。
2. 出门后，通过明确配置的受信远程通道连接同一台电脑。外网场景必须单独实测，不能以局域网成功代替。

## 当前基础和缺口

以下是 0.4 的已验证基础，依据 product/native/README.md 与 evidence/native-20261003/acceptance-0.4.md；后续发布仍需复测。

| 能力 | 当前基础 | 1.0 要补齐 |
| --- | --- | --- |
| 原生应用 | 中文菜单图标、原生界面、实体按键 | 统一组件、焦点和各类页面状态 |
| 已有会话 | 读取本机已有会话，展示最新回复 | 项目组织、完整消息时间线、历史分页、阅读位置 |
| 原会话控制 | 快捷指令与语音确认发送成功 | 结构化答复、真实审批、真实停止及操作回执 |
| 语音 | 按住 Y 录音，松手识别，用户确认出字快 | 草稿修改、就绪提示、失败恢复、稳定耗时统计 |
| 内容 | 常见 Markdown、部分图片及 TeX 公式 | 图片放大、宽表格/代码阅读、成果入口、不可用解释 |
| 状态 | 桌面状态及最新回复 | 当前回合与请求绑定、最近活动、陈旧状态、通知 |
| 连接 | 当前局域网连接有效 | 独立启动、配对、重启恢复、地址变化、外网验证 |

当前桥接依赖本次 Codex 提供的调用上下文。独立启动与桌面重启后的接续尚未验证。现有原会话发送成功，不能证明审批、停止或其他控制动作已实现。

## 完整使用流程

1. 打开掌上助手，恢复上次配对的电脑和阅读位置。
2. 工作台优先显示需要处理的事项，再显示运行中任务和最近结束的回合。
3. 进入原会话，阅读上下文和最近活动。
4. 按住 Y 说话，松手识别；核对目标、修改文字，按 A 提交。
5. 看到发送中、源端已受理，以及后续实际状态；结果未知时先核对，不能自动重复提交。
6. 有问题或审批时进入待处理页，查看原请求并作出决定。
7. 返回其他任务。完成、失败或等待决定时收到提示。
8. 打开成果，查看实际文件、图片或代码变更，决定继续还是结束跟进。

首次配对、断线、无会话、无权限、请求已过期、服务预热等情况都有明确页面，不能落到空白屏或要求用户输入终端命令。

## 页面结构

| 页面 | 用户要解决的问题 | 主要内容 | 主要动作 |
| --- | --- | --- | --- |
| 工作台 | 现在最需要关注什么 | 待处理、运行中、最近结束，最近活动与更新时间 | 打开任务 |
| 会话 | 发生了什么，如何接着做 | 连续对话、活动、草稿、相关成果 | 语音输入、发送、打开操作菜单 |
| 待处理 | Codex 正在等我决定什么 | 问题/审批原文、目标、范围、有效选项 | 答复、允许本次、拒绝、稍后 |
| 成果 | 这次工作产出了什么 | 文件清单、变更摘要、预览、验证情况 | 预览、查看变更、返回原会话 |
| 连接设置 | 怎样保持可用 | 配对、连接诊断、语音就绪、字号、通知、版本 | 重连、撤销设备、调整偏好 |

工作台按“待处理 → 执行中 → 最近结束”排序，同组按最近活动排序。保持当前焦点对应的任务，不因后台排序变化把 A 键操作转到另一条任务。允许固定项目、隐藏会话；默认不展开无关项目的内容。

## 功能要求

### 工作台与会话

- 会话保留原 hostId、threadId 和项目来源；任务标题改名不影响关联。
- 以用户消息、助手回复、用户可见执行活动构成时间线。不得展示内部推理、凭据或未经授权的私密数据。
- 历史内容按需分页，记录消息 ID 与阅读锚点。加载历史或新回复不能改变当前阅读段落。
- 阅读历史时出现“有新回复”，由用户选择回到最新；处于底部时才自动跟随。
- 切换任务后保留各自的草稿、滚动位置和展开状态。提交始终使用草稿创建时明确绑定的目标，切换后要求重新核对目标。
- X 打开当前任务操作菜单。可用动作来自实际能力列表，不支持的动作说明原因。
- 新建会话作为次级入口：选择项目、录入任务、核对后创建；不会因为打开工作台而自动创建或恢复任务。

### 语音与文字输入

- Y 按下开始，松手停止并转文字；保留 30 秒上限，短误触不提交。
- 录音中显示麦克风状态和剩余时长；识别中显示明确反馈。预热未完成时显示“语音准备中”，不能假装无响应。
- A 确认发送；B 放弃当前草稿；按住 Y 可重录。中断或重录前保留可恢复的上一份草稿。
- 首版文字修改提供按词移动、删除、插入和软键盘；语音补录可替换选中片段。每次修改都给出完整预览，不静默改写用户意思。
- 断网或识别失败保留草稿/录音并提供重试；超时的发送不能自动重发。
- 录音存储位置、保留期限、占用空间和手动删除入口可见。默认不上传云端，不将原始音频写入诊断报告。

### 问题与审批

- 结构化问题呈现原文及选项，可按原请求填写自由文本。问题答复与普通会话消息分开。
- 审批显示原任务、请求类型、具体动作、实际授权范围、原因及有效决定。
- “本次允许”只在源端确实提供对应语义时出现。若原请求授权范围更广，必须完整显示，不得把显示出来的两个文件误说成权限边界。
- 默认不选择永久允许；返回或稍后处理不会发送拒绝。审批不提供“全部自动通过”。
- 请求绑定 hostId、threadId、turnId、requestId 与版本。提交前验证仍然有效；电脑已处理时更新为“已在电脑处理”。
- 按源端回执显示已受理，按后续事件显示已处理。源端未确认时不得先消除待处理事项。
- 真实接口不可用时显示具体能力限制。发送“同意”或“停止”等文字不能冒充审批或停止动作。

### 运行状态与通知

连接状态与任务状态分别显示。

| 维度 | 状态 | 判定要求 |
| --- | --- | --- |
| 连接 | 已连接、重连中、离线、信息过期 | 可核实的服务连接和更新时间 |
| 任务 | 执行中、等待回答、等待审批、空闲、本轮结束、失败、已停止、未知 | 对应原回合的状态或事件 |
| 活动 | 最近工具动作、用户可见进度说明 | 原始事件；无事件时写“暂无新的活动信息” |

- 每次更新保留源时间和掌机观察时间；断开后保留缓存并标明最后更新时间。
- 空闲、本轮结束和整个项目完成不能互相替代。项目验收只能来自明确结论，不能依据一条回复结束推断。
- 不以 CPU、进程存在、文件修改时间推断模型仍在工作。无新输出只能提示多久未更新，不能直接判定卡死。
- 无可靠比例时不展示完成百分比；显示已知步骤、最近活动和耗时。
- 待处理、失败、本轮结束产生一次通知，去重且可静音。切出当前任务仍能看到未读标记；不为获取状态反复向模型发问。

### 成果与内容阅读

- 成果绑定原会话及回合，明确生成/修改的路径和类型；不能仅靠模型声称“已生成”就认定文件存在。
- 图片保持比例，支持适屏、放大、平移和返回；载入失败可重试并解释原因。
- 代码及宽表格支持横向阅读；竖向阅读位置保留。公式支持适屏与放大，长公式不静默截断。
- 文本、图片和支持格式的预览应在掌机完成；不支持格式仍展示名称、类型及明确限制。
- 代码变更优先呈现文件列表、增删摘要和只读差异。提交、合并、发布不属于本版默认动作。
- 产物完成摘要分别说明做了什么、修改了什么、验证了什么、还有什么未完成。

### 连接与远程使用

- 电脑伴随服务可独立启动，显示是否接入当前 Codex 实例。不能依赖用户在某个对话中重新运行命令才能恢复日常使用。
- 配对使用短时凭据或本地确认，掌机保存可撤销的设备身份。数据、图片、成果、动作接口全部鉴权。
- 电脑重启、桌面更新、IP 改变、掌机休眠恢复后自动重新发现并协商能力；无法恢复时指出具体原因和可执行下一步。
- 连接适配器跟踪源实例版本，不使用过期请求路由；当前私有适配路径不能作为长期兼容承诺。
- 外网接入选择经过验证的加密通道，独立于聊天/状态协议；不直接把控制端口公开到互联网。不会默认购买服务或把会话内容送到公共中转。
- 首次配对后，正常远程会话应能在掌机完成。电脑关机或远端服务不可用时如实显示离线。

## 与 Codex Desktop 的接入边界

| 操作 | 0.4 基础 | 1.0 要求与闸门 |
| --- | --- | --- |
| 列出已有会话 | 已实测 | 项目/来源准确，刷新不创建任务 |
| 读取回复 | 最新回复已实测 | 多轮历史、分页、锚点恢复 |
| 向原会话发送 | 已实测 | 实例重启后仍可恢复，回执及幂等可靠 |
| 当前活动和等待原因 | 不完整 | 取得真实事件或明确的受限状态 |
| 结构化问题答复 | 未验证 | 对应原请求 ID 的答复闭环 |
| 审批与拒绝 | 未接入 | 同一桌面实例的原审批处理闭环 |
| 停止当前回合 | 未接入 | 真实停止请求及最终状态 |
| 新建会话 | 本产品未接入 | 用户主动确认后创建并返回原 ID |
| 成果与差异 | 不完整 | 原会话产物可验证、可查看 |

先用隔离的安全测试任务验证接口，不中断或批准用户其他真实任务。另开 CLI 或 app-server 不算控制当前桌面实例。若关键能力确实不开放，应记录已尝试路径、限制证据和替代方案；此时只能交付受限版本，不能判定完整 1.0 通过。

## 实现结构

保留当前已验证的原生运行、字体、TLS、语音和内容渲染基础，逐步替换页面层。建议分为：

1. 掌机应用：页面、统一焦点、按键、草稿、缓存、通知与内容阅读。
2. 电脑伴随服务：配对、连接恢复、状态投影、媒体处理、常驻语音服务。
3. Codex 适配器：真实会话、回合、事件、问题及动作回执；能力版本化。

内部最小对象为 Host、Session、Turn、Message、Activity、PendingAction、Draft、Artifact、ActionReceipt。每个对象保留原 ID。源事件按序列/游标去重；重连先快照再补增量。源端缺少推送时使用有界轮询并显示信息新鲜度。

发送回执至少区分草稿、发送中、源端受理、失败、结果未知。请求编号持久化；结果未知不自动重复发送。传输连接成功不等于动作执行成功。

## 性能和可靠性目标

以下是待测目标，不是当前已通过指标。

| 项目 | 目标与测量条件 |
| --- | --- |
| 按键反馈 | 本地反馈 P95 ≤100ms，至少 100 次操作 |
| 状态同步 | 健康局域网下源事件到显示 P95 ≤3 秒，至少 30 次变化 |
| 短句识别 | 模型就绪、健康局域网、3～10 秒普通话样本，松手到草稿 P95 ≤3 秒，至少 30 条 |
| 语音冷启动 | 独立测量并显示准备状态，不混入热态速度宣传 |
| 首屏 | 服务在线且已配对时，打开后 3 秒内显示可用缓存或最新任务，持续更新 |
| 重连 | 网络恢复后 10 秒内开始恢复状态；未知动作结果先核对 |
| 连续使用 | 2 小时真机运行，至少 20 次切任务、10 次语音和多次断连，不丢草稿、不重复发送 |
| 重启恢复 | 电脑服务、Codex、掌机分别重启后验证，不能只重启模拟服务 |

外网指标单独报告网络条件、样本量、P50/P95和失败数；不直接复用局域网指标。记录识别错误率，不能只追求快而牺牲可理解性。

## 实施顺序与交付条件

| 阶段 | 可检查交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| 一 产品与视觉 | 本 PRD、三张主页面样稿、按键及状态规范、验收清单 | 核心流程明确；视觉为同一产品体系 |
| 二 接入验证 | 原会话/事件/问题/审批/停止能力矩阵，独立启动恢复原型 | 每项有实测结果；关键缺口明确，不藏进界面 |
| 三 一条完整流程 | 工作台 → 会话 → 语音 → 待处理 → 成果全部联动 | 在真实任务上可完成全程，页面不能只填静态示例 |
| 四 稳定与远程 | 配对重连、离线状态、通知、外网验证、持续运行报告 | 验收清单逐项通过，阻断项为零 |

现有版本保留可用，升级提供回滚，不能用新设计覆盖用户录音、配置或已有任务。视觉样稿不算可运行产品；安装成功不算完整使用验收。

完整 1.0 必须让用户在电脑不在手边时，从了解任务到处理决定、继续工作、查看结果走通一次真实工作，并经过持续运行与恢复测试。存在必需控制能力缺口时，发布名称和说明必须标为受限预览版。
